| Metric | Target |
|--------|--------|

## 6.6 Proxy queue

```
if backend.group.full OR network.online >= soft_cap:
  send player → limbo
  position = redis.incr queue:group
  estimated = position / release_rate
  when slot free → transfer FIFO
```

Soft cap 4500, hard 5500 (tune). Anti-bot before queue.

## 6.7 Database tuning (MariaDB)

```ini
innodb_buffer_pool_size = 40G   # ~60% RAM on DB host
innodb_log_file_size = 2G
innodb_flush_log_at_trx_commit = 2
max_connections = 800
thread_cache_size = 100
tmp_table_size = 256M
max_heap_table_size = 256M
```

App side: HikariCP `maximumPoolSize` 5–10 **per server**; never 50×40 servers.

Indexes: all UUID lookups, `season_id+rating`, ledger time.

## 6.8 Redis

- Cluster mode; ACL users per app.
- Keys: `profile:{uuid}`, `queue:{group}`, `online:{server}`, `lock:sync:{uuid}`.
- TTL profiles 30–60m; heartbeat servers 5s.
- Pub/sub channels listed in FunnyCore.

## 6.9 Autoscale arenas

Pterodactyl Wings / custom:
1. BW queue depth > threshold → start `bw-arena-n` from image.
2. Register to Velocity via FunnyProxy API.
3. Empty 10m → stop & destroy.

Slime maps loaded from templates; never commit player worlds.

## 6.12 Network / DDoS

- TCPShield / OVH Game / Path.net in front of Velocity.
- Only proxy IPs whitelist to backends.
- Rate-limit new connections; BotSentry.

## 6.13 Load test plan

1. 500–2000 fake players (Mineflayer / custom) through proxy.
2. Transfer storms Lobby↔Surv.
3. BW fill/start/end cycles.
4. Verify: no inv dupe, FC ledger OK, queue fair.
5. Chaos: kill one lobby, one redis replica, one arena.
